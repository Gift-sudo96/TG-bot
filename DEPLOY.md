# Як перенести бота на хостинг

Простими словами: на сервері має цілодобово працювати одна програма.
Не сайт, не сторінка — саме програма, яка постійно висить у пам'яті
і раз на пів хвилини дивиться, чи не пора комусь нагадати.

---

## Спершу перевір, чи підійде твій хостинг

Постав собі три питання:

| Питання | Треба |
|---|---|
| Чи можу я зайти на сервер через SSH і набирати команди? | **так** |
| Чи можу я запустити програму, яка працює постійно? | **так** |
| Це «хостинг для сайтів» з панеллю, куди заливають файли по FTP? | **не підійде** |

Звичайний хостинг під сайти не годиться. Там програма живе лише ті
секунди, поки хтось відкриває сторінку, а бот має бути живим завжди.

**Потрібен VPS** — це маленький окремий комп'ютер у дата-центрі,
до якого ти під'єднуєшся через SSH. Найдешевші коштують 3–5 € на місяць.
Безкоштовний варіант — Oracle Cloud Always Free.

---

## Чого немає на GitHub і чому

У репозиторії лежить **увесь код**, але свідомо бракує двох речей:

**`.env`** — там токен бота і Telegram ID. Якби він потрапив у git,
ботом зміг би керувати будь-хто, хто побачив репозиторій.
Цей файл створюється на сервері руками, один раз.

**`venv/`** — тека з бібліотеками. Вона збирається під конкретну
операційну систему, тому з Windows на Linux не переноситься.
На сервері збирається заново однією командою.

Базу `reminders.db` переносити не треба — вона створиться сама.
Якщо хочеш зберегти вже наявні нагадування, скопіюй її окремо
(див. розділ «Перенести стару базу»).

## Google Cloud: безкоштовна машина назавжди

Найдешевший робочий варіант. Машина e2-micro не має терміну дії й не
відбирається за простій — на відміну від Oracle, який забирає сервери,
де завантаження процесора за 7 днів менше 20%. Бот-нагадувальник майже
весь час спить, тож під це правило підпадає.

Потрібен обліковий запис Google і банківська карта для підтвердження
особи. Списань не буде, поки тримаєшся в межах нижче.

### Три межі, за які не можна виходити

| Параметр | Тільки так |
|---|---|
| Регіон | `us-central1` (Iowa), `us-west1` (Oregon) або `us-east1` (S. Carolina) |
| Тип машини | `e2-micro` |
| Диск | **Standard persistent disk**, до 30 ГБ |

Інший регіон, більша машина або SSD-диск — і почнуть капати гроші.
Це головна пастка Google Cloud.

Зовнішня IP-адреса безкоштовна, поки прив'язана до працюючої машини.
Не резервуй статичну — за невикористану Google бере плату. Звичайна
адреса може змінитись після перезавантаження, але боту це не заважає:
він сам стукає до Telegram і вхідних з'єднань не приймає. Змінилась —
просто подивись нову в консолі, щоб зайти по SSH.

### Створення машини

Консоль → **Compute Engine** → **VM instances** → **Create instance**

- **Region**: `us-central1 (Iowa)`
- **Machine configuration**: General purpose → E2 → **e2-micro**
- **Boot disk** → Change → **Ubuntu 24.04 LTS**, тип диска
  **Standard persistent disk**, 30 GB
- **Security** → Manage Access → **Add manually generated SSH keys**
  → вставити свій публічний ключ
- Firewall не чіпати: боту вхідні порти не потрібні

Важливо: **останнє слово в рядку ключа стає іменем користувача** на
сервері. Ключ, що закінчується на ` serhii`, дасть логін `serhii`.

### Підключення

Скопіювати **External IP** зі списку машин і в PowerShell:

```
ssh -i C:\Users\User\.ssh\gcloud_bot serhii@ЗОВНІШНІЙ_IP
```

Далі — установка з наступного розділу.

## Установка: три команди

Зайшовши на сервер по SSH:

```bash
git clone https://github.com/Gift-sudo96/TG-bot.git
cd TG-bot
bash deploy/install.sh
```

Перший запуск скрипта створить файл `.env` і зупиниться з підказкою.
Відкрий його і впиши свої дані:

```bash
nano .env
```

Три обов'язкові рядки:

```
BOT_TOKEN=8123456789:AAH...           # від @BotFather
ALLOWED_IDS=547696309,388521288       # кому дозволено користуватись
NAMES=547696309:Сергій,388521288:Аріна
```

Зберегти: `Ctrl+O`, `Enter`, вийти: `Ctrl+X`.

Тепер запусти скрипт ще раз:

```bash
bash deploy/install.sh
```

Він поставить Python, бібліотеки, зареєструє бота як службу і запустить.
Усе, бот працює.

### Що робить скрипт

1. ставить `python3` і потрібні пакети
2. збирає `venv` і ставить бібліотеки з `requirements.txt`
3. закриває `.env` від чужих очей (`chmod 600`)
4. створює службу systemd, щоб бот піднімався сам після перезавантаження
5. запускає і перевіряє, що він справді ожив

---

## Керування ботом

```bash
sudo systemctl status tg-reminder-bot      # чи працює
sudo systemctl restart tg-reminder-bot     # перезапустити
sudo systemctl stop tg-reminder-bot        # зупинити
journalctl -u tg-reminder-bot -f           # дивитись лог наживо
```

Найкорисніше — останнє. Якщо щось не так, причина буде саме там.

---

## Оновити бота після змін у коді

```bash
cd TG-bot
git pull
sudo systemctl restart tg-reminder-bot
```

`.env` і база при цьому не чіпаються.

## Резервні копії

Раз на добу зберігати копію бази:

```bash
crontab -e
```

додати рядок (підстав свій шлях, дізнатись його — команда `pwd`):

```
0 3 * * * /home/ubuntu/TG-bot/venv/bin/python /home/ubuntu/TG-bot/deploy/backup.py
```

Копії лягають у теку `backups/`, зберігаються останні 14.
Перевірити вручну:

```bash
venv/bin/python deploy/backup.py
```

## Перенести стару базу з комп'ютера

Якщо на комп'ютері лишились активні нагадування, скопіюй базу на сервер.
На **Windows**, у теці проєкту:

```
scp reminders.db ubuntu@IP_СЕРВЕРА:~/TG-bot/reminders.db
```

Робити це треба, коли бот на сервері зупинений:

```bash
sudo systemctl stop tg-reminder-bot
# ... копіювання ...
sudo systemctl start tg-reminder-bot
```

## Варіант через Docker

Якщо хостинг працює з контейнерами:

```bash
git clone https://github.com/Gift-sudo96/TG-bot.git
cd TG-bot
cp .env.example .env
nano .env                 # вписати токен і ID
docker compose up -d
```

База й лог лежатимуть у теці `data/` поруч і переживуть перезбірку.

```bash
docker compose logs -f    # лог
docker compose restart    # перезапустити
docker compose down       # зупинити
```

## Найчастіші проблеми

**`Conflict: terminated by other getUpdates`**
Десь працює другий примірник бота. Найчастіше — той, що лишився на
комп'ютері. Telegram дозволяє тільки одне підключення. Зупини зайвий.

**Бот мовчить, у логу порожньо**
Перевір, чи служба взагалі жива: `systemctl status tg-reminder-bot`.
Якщо ні — `journalctl -u tg-reminder-bot -n 50` покаже причину.

**`Unauthorized`**
Токен у `.env` неправильний або зіпсований. Бот сам напише, що конкретно
не так: скільки символів і двокрапок знайшов.

**Нагадування приходять не в той час**
Сервер може стояти в іншому часовому поясі. Боту це не заважає — він
рахує час за `TZ_NAME=Europe/Kyiv` із `.env`, незалежно від системного.
Якщо переїдете в інший пояс, поміняй цей рядок.

**Змінив `.env`, а нічого не змінилось**
Налаштування читаються при старті. Потрібен `sudo systemctl restart tg-reminder-bot`.
